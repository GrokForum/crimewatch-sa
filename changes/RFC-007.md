## Goal

Put the missing 21–27 November 2026 daily-sweep items into `data/sweeps.json`, in the format the `/daily-sweeps/` page already expects, each with a fetched source on the reviewed host list and one of the five fact labels. Leave empty lean days that truly had no fetched-source item. Add the official parliamentary host needed for the 27 Nov citation. ## Root cause

The public page is built at site-build time from `data/sweeps.json` in this repository. The morning routine updates the private Hub and local operational notes, but does not write (or open a pull request for) `data/sweeps.json`. When RFC-005 landed, 22–25 Nov were stored as empty lean stubs, and 26–27 Nov were never added. The live site was later deployed from `crimewatch-sa` `fa348088`, so it faithfully shows that frozen catalog. The “Edition of 20 November 2026” banner is the quarterly-figures edition, not the sweeps calendar; it is not changed here.

## Durable fix (routine prompt addition)

The daily-sweep routine should, on every run, also update this repository’s catalog — not only the private Hub. Proposed addition to the routine prompt, for the owner to paste:

After the Hub update, write that run’s public edition into `data/sweeps.json` in GrokForum/crimewatch-sa, on the fixed branch `sweep-feed`, never on `main`. Update the single existing draft pull request from that branch; open a draft pull request only if none exists. Use the existing catalog schema (date, compiled_sast, summary, items with id, kind, title, place, summary, one of Proven / Established / Alleged / Disputed / Not established, optional publishable handles, and sources with title and https URL). Include only items that have a fetched source URL on the reviewed host list used by `pipeline/sweeps.py`. If an outlet is not on that list, omit it, note it as pending review, and cite the same fact from an already-reviewed host if one was fetched. Empty days must use the exact lean wording already required by the catalog, and must not name an unsourced incident or place. Apply the POPIA rules: no living private person’s name, no exact ages of minors, no bot or teammate names, no local file paths, no operational-notes wording. Keep 20 Nov and any already-reviewed items unless a later reviewed change replaces them. Run the tests, the site gate and review_kit against the new head. Do not merge and do not deploy: that never-merge and never-deploy rule is enforced by instruction only, not by a technical control. A later named owner GO is required before the catalog reaches crimewatch.grokforum.site. Deploy builds must leave out `CW_INDEXABLE` (indexing stays off until the owner reopens it).
